审查结论：未发现尚未解决、会改变当前 Qwen 确认结论的实质错误。主结果可复算，仍是频谱方法未通过预声明门槛。审查发现两项审计器缺口，主任务已修复，本审查已验证修复；它们没有污染现有原始实验记录。

## 1. 发现与修复复核

### P2：审计器未绑定子集元数据——已修复

原 `audit_study.py` 校验了视频 ID 和问题正文，但没有逐字段比较记录中的 `area`、`tags`、`reasoning` 与官方问题文件。后续统计却使用记录中的这些字段定义题型，因此“通过完整性检查”仍可能包含错误子集。

在隔离的临时副本中，删除 `perception_test:video_10267:mc:3` 的全部 31 个条件记录中的 tags，保留官方问题文件及其哈希不变，原审计仍返回 `passed_integrity_checks`；主子集题数由 77 变成 76。此探针不改动真实文件。在真实记录上独立核验，所有子集字段本来均与官方文件一致，所以当前分数和区间不受此缺口影响。

修复增加了官方元数据逐字段比较以及配置 query ID 的完整性检查。相同探针现在被拒绝，错误为 `Question tags metadata differs from the official source`。证据：

- `outputs/independent_experiment_review/auditor_mutation_probe.json`
- `outputs/independent_experiment_review/auditor_regression_verification.json`

### P2：次要 reader 可被标成主协议成功——已修复

原 `frozen_v1_success` 对任意 reader 的比较结果计算同一阈值，没有限制固定 Qwen 主实验身份；因此次要迁移实验理论上也可能被标为主协议成功。该风险来自字段适用范围，不涉及本次读取 Smol 结果。

修复将主实验适用性绑定到 backend、模型 ID、revision、冻结协议，以及本次 questions/study/prompt/backend 文件哈希。非主实验返回 `frozen_v1_success=null`，描述性阈值结果另列。

对实际修复源码做轻量分支测试，五例均通过：绑定主实验且正结果为 true；未绑定、次要 Smol、错误 revision 均不适用；当前主负结果为 false。另对四个绑定哈希逐一替换，均使绑定失效。测试中的正结果是人工控制值，没有访问 Smol 中间结果。复测版本 SHA-256：

`7e4b34f253011110e78a848660af44c2b74d44b6fffbb496ed66b5e3e0b8e788`。

## 2. 统计与结果文档

从官方 QA 元数据重新定义三个子集，独立核算 5,642 条记录、93 个分数组及 72 个配对视频 bootstrap 对比。分数组最大绝对误差为 1.11e-16；全部 10,000 次、seed17 区间与正式报告一致。原始记录中的预测字母、零基索引、官方真值、奖励及子集字段全部一致。

| 主预算、时序/状态题型 | 视频宏差值 | 95% 配对视频区间 | 逐题改变 |
| --- | ---: | --- | --- |
| spectral − kcenter | −8.0808pp | [−19.6970, +2.0202]pp | 2 赢、4 输 |
| spectral − temporal_centered | −2.2727pp | [−10.6061, +4.5455]pp | 2 赢、2 输 |

主子集确为 77 题、33 视频。bootstrap 的单位是视频内平均差，未把同一视频的题或缓存复用行当成独立重复。视频宏平均与逐题微平均在文档中有明确区分。结果文档主 QA 表的 33 个数值均与正式报告按两位小数显示一致。

5,642 条记录含 3,863 个独立 forward ID；所有 forward ID 均根据原 run identity、问题、payload 及实际用户提示重新计算一致。全帧参考在不同 budget 行重复出现，不能当成额外独立前向。成本文档已披露缓存复用、顺序运行、热身及完整观察成本，不能据此作受控速度优势声明。

区间跨零不支持“主指标确定变差”，也不支持“优于基线”。全部问题上的次要负区间没有经过多重比较校正，文档已限制其解释。memory 富集、未知参与者、短视频及预训练污染的局限均有披露。

证据：`outputs/independent_experiment_review/qwen_recomputation.json`。

## 3. 开发十方法公平性与标签隔离

开发构建器限制原八个视频和层 0，仅接受隐藏轨迹、时间戳和帧清单，不接受问题、QA 真值或动作标签。十种方法均保留首尾、四个帧对、八张真实 RGB 帧，全部 80 个 NPZ 的持久化大小均为 3,539,820 bytes。

用独立 SVD 坐标与 `numpy.interp` 重算八视频的全部 3,480 个候选集合的谱目标、去均值时域目标及最大最近邻平方半径，最大绝对差为 1.15e-13。检查通过：

- 两种目标共享同一个完整 435 集合候选空间和固定首尾条件。
- 全局 exact 与半径约束 exact 均选中各自允许集合的全局最小值。
- 两个 swap 分支均满足原 k-center 半径界，并到达记录所称的单次交换局部最优。
- 时间目标按原始通道数归一化，Gram/SVD 约化没有改变复频谱残差或 centered-time 目标。
- 目标表和实际选择不读取标签；动作覆盖与后续 QA 只评价输出。

共享穷举表与联合构建耗时不等于每种方法的独立部署耗时；代码已在计时范围中写明，不能把该联合时间用于宣称某一种方法更快。开发数据已经用于后续探索，十方法结果不能替代失败的首轮确认，也不能把已查看结果的四十视频再当作新确认集。

证据：`outputs/independent_experiment_review/refinement_recomputation.json`。另在 `refinement_payloads.json` 中保存了 80 个实际 NPZ 的字节/内容哈希、原图逐像素及时间戳核验，512 张开发源帧重新哈希后与隐藏提取记录一致。

## 4. 绘图与动作指标核对

`plot_confirmation.py` 对 reader 输入要求 `status=complete`，选择 B4、指定子集、指定 baseline，并将宏差和区间统一乘 100 后画为百分点。当前 Qwen 点位及短动作覆盖的两项点位与正式报告一致。动作图的分母确为 144 个可观察短动作、30 视频；频谱实际保留 28/144，28.34% 是视频宏覆盖，不能写成事件微平均。

本次未读取未完成的 Smol 汇总，因此没有生成或验收最终三面板图。绘图标题中的 77/33、144/30、40 是当前冻结实验的固定数值，已逐项核对；该脚本若用于不同数据，需同步检查或从输入统计生成标题。最终导出仍应在两个 reader 完成后进行视觉检查。
