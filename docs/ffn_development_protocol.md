# FFN 开发诊断协议

2026-11-01。首个 `video_10993` 的 16 帧工程试点已经完成后，预先确定其余七个原开发视频沿用相同配置。此扩展是描述性开发诊断，不是独立确认实验，不能用于宣称记忆方法有效。

1. 视频集合固定为原 8 个开发视频，按 ID 字典序逐个运行；读取中性提示 `Describe the visible events.`，不读取问题、答案或动作标注。每个视频重新从原文件均匀采 16 帧，保存实际源 PTS、目标时间网格及哈希。
2. 固定 Qwen3-VL-2B revision、BF16、每帧最多 65,536 像素、batch=1；采 decoder 0/13/27 层的输入、attention 增量、FFN 前残差、归一化 FFN 输入、FFN 增量和 FFN 后残差。FFN 后状态在 DeepStack 加法之前立即克隆。
3. 每次仅一个 GPU 进程，allocator fraction=0.65，CPU 两线程，最长 300 秒；RAM/VRAM/温度监测同 `resource_guard.py`。每个视频启动前重新预检；任何失败均停止后续扩展，不自动降低精度或增大额度。限额不代表已定位或修复蓝屏原因。
4. 每层在全部视觉位置上按原 dtype 验证 attention、FFN 残差加法。频谱仅沿 8 个时间格计算，使用正交 DFT、一侧倍数和完整交叉项；均值归约舍入单独计入闭合式。
5. 对每层报告 FFN 前后绝对时间能量比、DC 能量比、时间能量占比变化，并列出 attention 对照。特别区分“时间信号幅度上升”和“DC 被抵消导致归一化占比上升”。跨视频只报逐视频值、中位数与范围，不从这 8 个开发视频挑显著层。
6. 此探针不产生 QA 效果、长期记忆收益或因果归因结论。若最终层频谱比值发生明显变化，只能提出后续干预问题；需要同预算的记忆读出和独立样本继续验证。

首个运行的源码快照保留在 `outputs/ffn_qwen3_dev16_v1/source_snapshot/`。后续代码仅加强开发视频 ID 校验、显式关闭 attentions 和设备映射校验；各次运行保存实际源码哈希，不能把它们称为完全相同源码版本。
