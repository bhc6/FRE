# V2 单位归一化读出：开发结果与机制审计

日期：2026-11-01。范围：已经见过的 V1 训练与 validation 数据。本报告没有读取新增 32-source 数据的模型分数，也没有把原 V1 test 重新包装成未见测试集。

**结论：归一化修复了干预幅度过小，但本轮没有得到跨选项旋转保持的准确率收益。** 原始顺序中 time-MLP、cap .3 为 18/40，对照 17/40；同一 40 道题的三种循环选项顺序合并后，双方均为 52/120，time 的 source-macro 还下降 0.4464 个百分点。time 的 NLL 改善保留，且优于 constant；应如实报告为本开发集上的概率评分改善，不能改写为准确率或长期记忆改善。Spectral 在本轮不优于 time。

## 1. 可复算范围与统计约定

- 独立 CPU 脚本：`outputs/normalized_development_analysis_v2/analyze.py`；全精度结果：同目录 `report.json`；核验记录：`checks.json`。
- 脚本 SHA256：`48aa81ab13162098afd10706f68edc9d53e52e1311a5c5058984a264987bd356`。5,450 项核验通过，覆盖 records/NPZ/checkpoint/source/protocol 哈希、完整矩阵、逐例选项分数、输入 ID、配对输入、零控制与撤销后的全词表一致性、KL 重算、static 无 gold。
- 训练为 32 个 source、142 道有标签题与 64 个无标签 static 条件。原序 validation 为 8 个 source、40 道题与 16 个 static 条件。`validation_screen` 和 `validation_rotations` 均完成、ResourceGuard 正常退出后才读取完整分数。
- 原序全部六候选均报告。旋转检查只包含此前安排的 cap .3 三候选；没有 cap .1 的旋转结果，不推断它们的旋转稳定性。
- NLL/CE 均为对原始 A/B/C 三个 logit 做 float64 log-softmax 后的真实标签负对数概率；不是完整词表生成 NLL。Margin 定义为 gold logit 减最大错误选项 logit；所有差值为方法减配对对照。
- Micro 对问题平均；source-macro 先对每个视频的问题平均，再对 source 等权平均。旋转时每道题先对三次呈现平均，仍然只有 40 道题、8 个 source；120 是呈现次数。由于每题均恰有三次，表中的 120 次呈现平均与先按题平均数值相同。
- 所有区间使用 10,000 次 source-cluster paired percentile bootstrap、随机种子 20261101。每次整体抽取 source，携带该 source 的全部问题、配对方法及旋转。准确率区间以百分点表示，NLL 区间以 nats 表示。
- **8 个 source、单个训练 seed、重复开发使用、六候选筛选与后续旋转检查，都使这些区间只能用于探索。** 未作多重比较校正。准确率变化全为零时 bootstrap 的 `[0,0]` 是当前样本退化分布，不证明总体严格等效。

## 5. 幅度与 cap 是否真正生效

CPU 仅加载控制器与已有缓存，不执行 backbone/tail。其最终每例最大 head ratio 与 GPU replay 记录的最大差不超过 `8.94e−8`。

| 方法 | Train head ratio 中位数 | Train capped heads % | Train gain 接近 .25 上限 % | Validation 原序 total ratio 中位数 | Validation capped heads % |
|---|---:|---:|---:|---:|---:|
| T .1 | .100000 | 80.81 | 0.341 | .095792 | 75.00 |
| T .3 | .300000 | 89.52 | 14.618 | .296069 | 87.50 |
| S .1 | .100000 | 56.03 | 0.198 | .076563 | 15.63 |
| S .3 | .185035 | 2.38 | 15.972 | .182738 | 1.41 |
| C .1 | .088021 | 0 | 0 | .088539 | 0 |
| C .3 | .088021 | 0 | 0 | .088539 | 0 |

“接近 gain 上限”定义为 `abs(gain) >= .95 × .25`；head ratio 为 `||delta_head||/||native_context_head||`，total ratio 为拼接全部 head 后的范数比，二者不能混用。C 的 .1/.3 cap 都未激活，实际输出一致，不构成两个不同强度的有效干预。cap 数值在 FP32 浮点容差内成立；实际 BF16 cast 后的范数不是本表保证的严格数学界。

这与 V1 的幅度极小、cap 数学上不可达不同。现在 T .3 的总体扰动已接近 native attention context 范数的 30%，继续将失败归因于“干预没有进入模型”不成立；但这也不证明任意方向的 30% 扰动都足够完成任务。

Oracle 没有持久化各 head raw gains，不能重建 gain saturation 或完整 capped-head fraction；表中只统计每例最大 ratio 是否到达 cap。`free_context` 实际为逐坐标 `tanh(raw) × .3||context||/sqrt(128)`，再做范数投影，是更广方向集合的坐标盒参数化，并非覆盖整个 L2 球的理想 oracle。四者参数维数、可达几何和有限优化难度均不同，不能把 103−90 直接归因于唯一的“频域子空间损失”。

仍可作两个有限判断：单位归一化确实让相同训练例获得更大且多数有利的可达扰动；最终 attention context 并非对所有干预方向都不响应。原始 time oracle 的有限优化失败不能否定所有原始 time 参数解，free-context 的标签辅助改善也不能保证一个共享低参数网络能泛化。

## 7. 下一步基线与停止条件

建议停止继续把“最终层八个现有 basis 的 gain/cap 调大”当主要改善路线。本轮已排除“该实现完全没有有效幅度”这一简单解释，却未取得旋转平均准确率提升；继续搜索更多 cap、seed、step 会扩大开发集选择偏差。NLL 改善应保留为可复验观察，同时冻结本轮结果。

下一项最有信息量的基线是**通用、训练预算相近的内部 bottleneck residual**。ReFT/LoReFT 已将冻结模型上的低秩隐藏表示干预作为参数高效适配方向，因此通用 adapter 应明确列为既有思想的容量对照，不称为新的长期记忆机制。[1]

若要单独区分“八 basis 方向集合”的限制，应优先在相同 attention-context 位置与相同 per-head cap 使用学习到的输出方向。例如拼接归一化 query/context 的 4096→3→2048 网络、不含输出 bias、零初始化输出矩阵，总参数 18,435；这只是可比较的后续设计建议，尚未训练或评估。

当前另行冻结的 `ffn_capacity_protocol_v2.md` 选择末层 FFN 输出上的 2048→4→2048 adapter，18,436 参数，可作为更广泛的容量对照。它改变了干预位置、norm 参考与函数集合，不能称作同强度的 attention 子空间消融；elementwise tanh 与全维输出 bias 也意味着“rank 4”描述网络瓶颈，不是严格四维线性残差子空间。其成败不能单独证明 attention mass 的因果作用。若后续转向中层，需作为独立实验先冻结层选择与预算，不能与本轮混为一次验证。

后续任何候选都应同时展示 micro、source-macro、NLL、repair/regression、选项旋转与 static 稳定性；在选择冻结前保持新增 source 分数未见。若通用容量对照同样没有稳健准确率收益，应暂停这一最后位置轻量适配设定，回到训练信号、数据规模或更早层的信息利用问题。现有结果不足以否定所有中层干预、所有 VLM 或所有长期多模态记忆机制。
